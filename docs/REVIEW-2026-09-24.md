# Product review, 2026-09-24

Cairn as it is today, against note-taking tools (Notion, Obsidian, Logseq, Apple Notes) and agent-memory tools, and against what people say about them on Hacker News, Reddit and the Obsidian and Logseq forums. The owner asked for this review with two extra questions: can Cairn be used for personal notes too, and what can it adopt from Notion.

## 1. Method and limits

1. Inventory of the code and docs at commit `a1b5304` (v0.1.8): MCP tools, CLI, console routes, content model, search, roadmap and non-goals.
2. A hands-on tour of the review console on the local instance at 129 pages, desktop and phone viewport.
3. Forum research: Hacker News threads from 2025-10 to 2026-09 opened and read; Obsidian and Logseq forum threads; Reddit reached only through search-engine snippets, because reddit.com is blocked from the tools used, so the Reddit material is thinner and mostly 2023-2024.
4. Notion's own help pages and release notes, 2025-04 to 2026-07.

Confidence: high on the inventory and console findings, medium on forum sentiment (developer-heavy sample), medium on Notion facts (sourced) and on effort sizes (estimates).

## 2. What Cairn nailed

These are the things forum users say they want and mostly do not get, and Cairn already has them.

1. **Every agent write is visible and reversible.** Recent changes shows who wrote (agent or person, with the client name), the change note, and a diff, with a restore button. The most repeated worry in the HN agent-memory threads is that agent-managed memory is a black box that a person cannot audit or prune; commenters say they trust only memory they curate themselves and prune by hand. Cairn's changes feed, per-revision diff and restore are exactly the answer, and the person/agent filter is a detail nobody else has.
2. **Wrong facts do not settle in for good.** The Freshness screen, `verified_at`, `list_stale_pages` on every surface and sources on revisions address the "poisoned memory" theme: one wrong line that spreads, and entries "confidently wrong" months later. Notion, Obsidian and mem0 have nothing like a verified date.
3. **Search is hybrid, keyword first.** BM25-style FTS5 with stemming and heading weight, fused with a small local embedding model, falling back to keyword mode and saying so. Recall@5 0.97 hybrid, 0.88 keyword. This matches the forum consensus that keywords are needed, embeddings help, and neither alone is enough. NEAR phrases and per-collection synonyms (ADR-076, ADR-077) go further than any of the compared tools.
4. **No LLM on the write or read path, private, self-hosted.** Several Show HN authors built their own memory layers because mem0-style products call an LLM on every write (slow and costly). Cairn's embeddings are background and local. This also answers the privacy complaint against Claude's own memory ("should exist locally, not on company servers").
5. **Cheap context, and a CLI beside MCP.** The home page states the cost: about 115 tokens a session for the CLI against about 3,100 for MCP. HN's "MCP is context bloat, once you have a shell use a CLI" crowd would recognise this. Most MCP servers publish no such number.
6. **Markdown, versioned, exportable, synced.** Pages are Markdown with `[[links]]`, `cairn export` and `cairn sync` between instances give the "no lock-in" that people cite as the reason they leave Notion. Offline is solved by the laptop instance plus sync, which beats Notion's page-by-page offline marking.
7. **Update over create.** The MCP instructions and skill push the agent to search first and update an existing page with a change note. This targets the "everyone writes, nobody reads" and duplicate-page complaints directly. The workspace summary sent with the instructions is a good touch.
8. **Sources and citations as first-class data.** Sources per revision, `check-sources` with Wayback lookup, JSON-LD on published pages. No compared tool ties a fact to where it came from at revision level.
9. **Tables with typed columns and relations, filtered in core.** Enough of Notion's database idea to hold an index or a stack list, without the formula and view machinery.
10. **Documentation discipline.** ADRs, directions, changelog and lessons in the repo. Rare in this category and relevant to the source-available positioning.

## 3. What Cairn misses

### 3.1 As an agent memory

1. **Draft versus promoted.** The forum answer to poisoning is "agents draft, a person promotes". Cairn has verified/unverified, which is close, but there is no state that keeps an agent's new page out of the agent's own search results until a person has looked at it. A page written by a prompt-injected agent is searchable by the next agent at once. Size M; needs an ADR because it touches search ranking and the MCP contract.
2. **Near-duplicate detection at write time.** `create_page` does not warn when a page with a similar title or high embedding similarity exists. The instructions ask the agent to search first; the tool could enforce it. Size S/M.
3. **A digest of agent activity.** Recent changes is a log, not a review queue. A person with 30 agent writes a day wants "what changed since I last looked, grouped by collection, with one-line summaries". The roadmap has this as "agent digest with approvals", later. Size M.
4. **Claude Code daily use is marked blocked** in the roadmap, and claude.ai over OAuth is unproven. The Phase 1 gate rests on this.

### 3.2 As a personal note tool

1. **No capture path.** Every forum source agrees: mobile capture in under two seconds decides whether a note tool is used daily, and this is where Obsidian loses (slow mobile start, sync trouble) and Apple Notes wins. Cairn's shortest path on a phone is: open the console, New page, type a title, pick a parent, type, save. There is no daily-note button, no inbox, no share-sheet target, no bookmarklet. Quick capture is on the roadmap as "later". This is the single biggest gap for the owner's note-taking wish.
2. **Links are by id, not by title.** `[[pg_490b7b6c605f416f]]` is fine for an agent and unusable for a person typing a note. Every note tool since Roam links by title with autocomplete. Without at least title resolution (`[[Projects]]` resolves if unique, else an error that lists candidates) a person will never write links in the console. Size M; ADR needed, since ids are the current contract.
3. **The editor is a bare monospace textarea.** No preview in place (preview is a server round trip), no link or tag completion, no keyboard shortcut for save. ADR-009 forbids a rich editor, and that decision stands, but a textarea with server-side preview beside it, `Cmd+Enter` to save and a link picker that posts a search are all within the ADR (forms and small progressive JS, no client application). Size S/M.
4. **Daily notes exist for the agent, not for the person.** `get_today_note` and `cairn today` exist; the console has no Today link, no previous/next day navigation, and daily notes are UTC-only (ADR-075 notes the CET midnight problem). Size S.
5. **No page properties.** Pages have tags, sources and verified date. Obsidian's frontmatter properties and Notion's page properties are how people track status, due dates, or ratings on a note. The workaround is one table row per page; that is what the Peptides collection does. Size L; a new ADR.
6. **Nothing that lets a page show a live list.** Obsidian Bases and Dataview, Notion linked databases: "pages tagged X changed this week" inside a project page. Cairn can only hand-link. Size M.
7. **No embed of one page in another.** `![[page]]` or `![[page#heading]]`, Notion's synced block. Size M.
8. **Task lists render but cannot be ticked.** A checklist you tick in place is Apple Notes' most used feature. Size S/M.
9. **Templates cannot be used from the console.** `create_page_from_template` and `cairn new --template` exist; the New page form has no template picker. Size S.
10. **No delete, no move, no attachment upload, no table creation from the console.** A person must ask an agent or use the CLI for four ordinary actions. The inventory lists them as console gaps. Size S each.
11. **Home page is built for a first visit, not a daily one.** "Connect an agent" takes half the screen; for the owner it should show today's note, recent pages, an inbox count, and stale pages worth a look. Size S.

### 3.3 Console UI and UX findings from the tour

1. Page view: the action row gives Publish and two PDF buttons the same weight as Edit; on a phone the buttons take three rows above the text. Move Publish and PDF under a "More" `<details>` or to the bottom. Size S.
2. Search results list the same page several times, one per passage. See bug 1 below.
3. Freshness lists 105 never-verified pages in updated order. Ranking by inbound links or recent reads would put the pages that matter first. Size S.
4. The phone layout works without script, text is readable, forms are usable. Navigation wraps to two lines at 375 px. Light mode was not tested in this tour.
5. The 404 page, footers ("129 pages, last backup today"), the copy-command buttons and the dirty-form guard are small things done well.
6. The table screen sorts and filters in the browser and links rows to pages. Saved views are missing (section 4).

### 3.4 Bugs found

1. **Console search bypasses the shared operation.** `packages/api/src/web/console.tsx:1972` calls `context.search.search` directly; MCP, REST and the CLI go through `searchPages` in `packages/api/src/operations.ts:289`. So the console gets no synonym expansion (ADR-077) and no one-entry-per-page grouping (ADR-057), which is why "zigbee coordinator" showed the same page four times. This breaks hard rule 14 (surfaces translate, they never decide). Fix: call `searchPages` and render its shape. Size S.
2. **Diagrams accepted by ADR-065 are not rendered anywhere.** Mermaid, Vega-Lite and Viz.js are decided, not built. Either build or mark the ADR as pending in the roadmap.
3. **PRD section 7 still says pages are BlockNote JSON and the front end is React.** The code stores Markdown and has no React. Doc and code disagree; the PRD is wrong.
4. Attachments and history are not exported; the static site export does not render tables; GIF has no thumbnail; the CLI has no `attachment delete`.

## 4. What to adopt from Notion, and from Obsidian, Logseq and Apple Notes

Notion is good at notes mostly because of its block editor, and ADR-009 rules that out on purpose. What carries over is the plumbing around the editor. Classes: (a) fits the model and is cheap, (b) needs the console to grow past ADR-009, (c) does not fit or is a PRD non-goal, (d) better done by the agent.

| Feature | Class | How it would look in Cairn |
|---|---|---|
| Quick capture (clipper, share sheet, widget) | a + d | `POST /capture` into an Inbox collection; an iOS Shortcut and a bookmarklet reach it, no app needed; the agent files, tags and links items later |
| Daily notes as the default place to write | a | Today link in the nav, previous/next, `[[2026-09-24]]` resolves to the day, a time zone setting |
| Databases with views | a for table views, b for board/calendar/timeline (PRD non-goal) | A saved filter, sort and column set on a table, stored as a row, rendered on the server |
| Linked database in a page (Notion), Bases and Dataview (Obsidian) | a | A fenced `cairn-query` block rendered on the server into a list or table |
| Synced blocks, embeds | a | `![[page]]` and `![[page#heading]]` rendered inline, one source, counts as a backlink |
| Callouts, toggles | a | GitHub alert syntax `> [!NOTE]` and a container that renders `<details>`; still plain Markdown, raw HTML stays off |
| Checklists ticked in place (Apple Notes) | a/b | One form post per item, works without script |
| Templates and template buttons | a | Template picker on New page; ADR-075 already stores templates |
| Page properties (Notion), frontmatter (Obsidian) | b, new ADR | Free-form typed properties on a page, shown as a panel and filterable |
| Link by title with autocomplete | b, new ADR | Title resolution for `[[Title]]`, a link picker backed by search |
| Unlinked mentions (Obsidian) | a | Search for the title minus pages that already link, in the backlinks panel |
| Favourites and recent | a | A tag or a small list in the sidebar |
| Relations shown on a row | a | Already a column type; render related rows on the row page |
| Autofill properties (Notion AI) | d | A "needs filing" list in the console; the agent tags and files |
| Q&A over the workspace (Notion AI) | d | Already what Claude plus search does |
| Rollups, formulas | c | PRD non-goal; ask the agent for a one-off |
| Comments, mentions, inbox, reminders | c | One owner, no scheduler; put dated tasks in a table and let the agent or Home Assistant remind |
| Email to Cairn | c for now | Needs an inbound mail provider outside the single container |
| Block editor, outliner, canvas | c | ADR-009; BlockNote is Phase 2; Mermaid for diagrams once ADR-065 is built |
| Offline | c | The laptop instance plus sync already does better than Notion's page-by-page offline |

Notion facts checked: view types and filters (notion.com/help/views-filters-and-sorts), relations and Formulas 2.0 (notion.com/help/relations-and-rollups), buttons (notion.com/help/buttons), web clipper and mobile widgets (notion.com/help/web-clipper, notion.com/help/mobile-widgets), offline limits (notion.com/help/use-pages-offline), Notion AI agents 3.0 (notion.com/releases/2025-09-18), hosted MCP as Markdown over OAuth (developers.notion.com/guides/mcp/overview). Notion's own MCP reads and writes pages as Markdown, which supports Cairn's choice.

## 5. Recommendation

Do not change the shape of Cairn. The agent-memory side is ahead of the tools people discuss. The note-taking side is missing plumbing, not an editor. In order:

1. **Fix the console search bug** (3.4.1) and the PRD section 7 disagreement (3.4.3). Small, and one is a hard-rule break.
2. **Capture sprint, size M.** `POST /capture` into an Inbox, a Today link with previous/next and a time zone setting, a template picker on New page, a home page for the owner (today, recent, inbox, stale). This alone decides whether the owner opens Cairn on a phone.
3. **Links for people, size M, ADR.** `[[Title]]` resolution with a clear error on ambiguity, a link picker in the editor backed by search, unlinked mentions in the backlinks panel.
4. **Markdown that works for notes, size S.** Callouts, toggles, tickable checklists, `Cmd+Enter` save, preview beside the textarea.
5. **Live lists, size M.** Saved table views and the `cairn-query` block. This covers most of what people use Notion databases for.
6. **Embeds, size M.** `![[page]]` and `![[page#heading]]`.
7. **Draft versus promoted, size M, ADR.** Agent-created pages stay out of agent search until a person has seen them, or at least rank lower and carry a badge. This is the one agent-memory gap that matters.
8. **Later, with an ADR each:** page properties, near-duplicate warning on create, agent digest.

Not adopted, on purpose: board, calendar and timeline views, formulas and rollups, a block editor, comments and mentions, reminders inside Cairn, email capture. Relaxing any of these means changing the PRD non-goal or ADR-009 first, not growing the console quietly.
