# ADR-039: A published page's sources are also JSON-LD, for machines to follow

Status: accepted
Date: 2026-09-15
Relates to: ADR-027 (sources), ADR-032 (the published wiki), ADR-034 (self-description), ADR-036 (checking sources), ADR-038 (cross-Cairn links as edges), PRD principle 6 (bridges between Cairns)

## Context

The roadmap's "Machine-readable citations on public pages" asks that public pages and the static site carry their sources not only as the visible list they already have (ADR-027, rendered by `packages/api/src/web/public.tsx` and `packages/cli/src/site-format.ts`), but as structured data too: schema.org `citation` and `isBasedOn`, so a search engine or an agent reading one page can follow its sources to the next without scraping prose.

Both surfaces already turn a source into a followable address when one exists (`sourceHref`, resolving a URL as is, a DOI to doi.org, a PubMed id to pubmed.ncbi.nlm.nih.gov), and render it as a link when it does. A plain citation with no address, such as "Smith 2021, J Pept Sci", renders as text only. Neither surface emits anything for a machine reader beyond that link: no `<script type="application/ld+json">`, no microdata.

Two schema.org properties fit two different things a source can mean. `citation` is the general case: this page refers to that work. `isBasedOn` is narrower: this page is a derivation of that other one, not just aware of it. ADR-038 gave every Cairn's published page one canonical address, `<origin>/w/<page-id>`; a source that is itself shaped like one is not an ordinary citation, it is this page naming the original it was copied or built from in another Cairn, exactly the case PRD principle 6 calls a bridge. That split needs no new input: it falls out of a source's own shape, the same way `cairn_link` fell out of a link's shape in ADR-038.

Nothing here should need fetching anything. Every fact used already lives on the page: its `sources` list and, for each one, what `sourceHref` already resolves it to.

## Decision

1. **Every published page (`/w/:id`) and every page in `cairn export --format site` carries one JSON-LD block in its `<head>`**, `@type: "WebPage"`, alongside the existing `<meta description>` and canonical link. Nothing renders differently; a machine reader gets a second, structured copy of what a person already sees in the page's Sources section.

2. **Every source becomes one entry in `citation`.** One that resolves to an address (`sourceHref` returns non-null) is `{ "@type": "CreativeWork", "url": <address>, "name": <source> }`; one that does not is the source's own text, as a plain string, schema.org's `citation` accepting `CreativeWork` or `Text` for exactly this reason. Nothing is dropped and nothing is guessed: a citation with no address stays addressless.

3. **A source shaped like another Cairn's page, `<origin>/w/<id>`, once resolved, is also added to `isBasedOn`**, as its plain URL. The shape check is the same one ADR-038 uses for a link in a page's body, applied here to a source's resolved address instead. A page can have several; `isBasedOn` is a list precisely because a page can be built from more than one original.

4. **No fetch, no new field, no new input.** Both new properties are computed from data the page already carries; whether the address is live, or really is what it claims to be, is still `cairn check-sources`'s job (ADR-036) and never this one's.

5. **The CLI's static export duplicates the shape check**, the same way `packages/cli/src/sources.ts` already duplicates `sourceHref` from `packages/core/src/sources.ts` (hard rule 16: the CLI's runtime cannot import `@cairn/core`). A test running the same cases against both keeps them in step, the same pattern `packages/cli/test/sources.test.ts` already uses for `sourceHref`.

## Consequences

1. One new small function, `isCairnPageAddress`, in `packages/core/src/sources.ts` and duplicated in `packages/cli/src/sources.ts`; one JSON-LD block added to `Shell` in `public.tsx` and to `shell` in `site-format.ts`. No new storage, no new port, no new MCP tool or REST field: this is a rendering decision on data already public.
2. `/.well-known/cairn.json`'s `cites` field (ADR-034) is unaffected. It answers a different question, which other Cairns this one names anywhere, at the whole-Cairn level; this ADR answers it per page, in the page itself, for whichever crawler reads that page directly rather than the self-description first.
3. A citation with no resolvable address contributes text to `citation` but nothing to `isBasedOn`: `isBasedOn` needs an address to name, by definition.
4. Sources are unchanged in every other way: still capped at 500 characters and 100 per page (`MAX_SOURCE_LENGTH`, `MAX_SOURCES`), still exactly what ADR-027 and ADR-036 already established. This only adds a second rendering of the same list.
5. Still `later` on the roadmap: "'Cited by', across Cairns" (this Cairn learning that another links to it) and "Discovery by following citations" (an agent walking outward along `citation` and `isBasedOn` itself). Both now have real, standard structured data to work from once they land.
