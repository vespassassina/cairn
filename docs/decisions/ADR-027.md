# ADR-027: Pages and rows keep a list of sources

Status: accepted
Date: 2026-09-14
Relates to: ADR-008 (revisions), ADR-011 (server instructions), ADR-013 (three surfaces), ADR-016 (export), ADR-023 (sync)

## Context

The roadmap item "Provenance: `sources` on every write" asked for where a fact came from, shown in the console. Agents write most of what Cairn holds, and a page that says a peptide was studied at 10 mcg/kg in rats is only as good as the paper behind it. The change note says why a write happened; nothing said where its facts came from.

The owner said "next item" and was asked three questions. They chose:

1. **Where sources live: on the page or row.** Each page and row holds a list. A write adds to it, and history shows which change added each one. Rejected: sources only on the revision, which would scatter them across history and leave the page itself with none; and both, which stores the same thing twice.
2. **Whether a write must name one: optional, prompted.** The instructions and the skill tell agents to add a source whenever a fact came from somewhere, but a write without one still goes through. Rejected: required on every agent write, which would make agents invent sources for summaries and moves.
3. **What a source is: a short text.** A URL, or a citation such as "Smith 2021, J Pept Sci" or "the owner, 2026-09-14". The console shows web addresses as links. Rejected: a structured object with a title, a URL and a date, which costs agents more to write and every session more to load.

## Decision

1. **`sources` is a list of strings on every page and row,** stored with it, and part of every revision's snapshot. Each source is cleaned before it is stored: runs of whitespace become one space, the ends are trimmed, and empty entries and repeats are dropped, keeping the first-seen order. A source is at most 500 characters ("cite it, do not quote it"), and a record holds at most 100. Core enforces both, so every surface gives the same error.
2. **In core, `sources` on a write is the whole list, and leaving it out keeps the list the record has.** A move, a retitle or a restore of a revision without the field keeps a page's sources rather than wiping them. A new record without sources starts with none.
3. **Agent writes add; they never remove.** MCP `create_page`, `update_page` and `upsert_row` take `sources`, and `update_page` and `upsert_row` add them to the ones already there. The CLI's `--source` (repeatable) does the same on `create`, `append`, `replace-section`, `write` and `upsert`. REST `PATCH` on a page adds too, and `PUT` on a row takes `add_sources` for the same purpose.
4. **Replacing the list is deliberate.** REST `PUT` on a page or row takes `sources` as the whole list, which is what import and sync need; left out, the list is kept, and sending both `sources` and `add_sources` is refused. In the console, the page and row editors have a "Sources, one per line" field that replaces the list. Removing a source is done there, or through `PUT`.
5. **History shows what each revision changed.** A revision view reports the sources it added and the ones it dropped, in the console, in MCP `get_revision` (`sources_added`, `sources_removed`) and in REST, and the CLI's `revision` prints them as `+ source:` and `- source:` lines. Revisions written before this ADR have no `sources` field; they report no change, and restoring one keeps the page's current sources.
6. **The console shows them.** A page shows a Sources section after its text; a row shows them beside the form. Web addresses (`http` or `https`, nothing else) are links with `rel="noopener noreferrer nofollow"`; everything else is plain text, escaped like all stored content.
7. **They travel with the content.** Export writes a `sources` line in a page's front matter and a `sources` list on a row, only when there are some; the format stays at version 2, since readers ignore keys they do not know. Import compares sources and sets them, so a record the export lists with none ends with none. Sync hashes `sources` only when a record has some, so a record without sources hashes as it did before this ADR: the first sync after the upgrade copies nothing, even against a server that has not upgraded. Every sync write sends the full list, empty included, so a removal on one side reaches the other.
8. **SQLite stores the list as JSON** in a `sources` column on `pages` and `rows_`, added to an existing database on start, with `[]` for every record already there.

## Consequences

1. A fact an agent writes can be traced to where it came from, and the owner sees the source beside the text without opening history.
2. Sources are prompted, not checked. An agent can still write without one, or cite something vague; the console shows it, and the owner can correct it.
3. The MCP tool list grows by one argument on three tools. Measured with `pnpm context-cost` on this repository's database: about 2,931 tokens a session before, 3,091 after, with the argument's description cut short and its limits checked in core rather than in the schema every session loads. The server instructions gain one sentence (1,493 of 2,000 characters). The skill description is unchanged, so a CLI session still pays about 115 tokens until it uses Cairn.
4. Rows without sources in MCP `query_table` results carry no `sources` key, so reading a table costs what it did.
5. A source is a claim about where a fact came from, not a copy of the source. Cairn does not fetch URLs or check citations.
6. "Freshness: `verified_at` on pages", the next roadmap item, is separate: a source says where a fact came from, not when it was last confirmed.
