# ADR-040: A Cairn accepts a citation notice, Webmention-shaped, from a trusted address or on review

Status: accepted
Date: 2026-09-15
Relates to: ADR-013 (three surfaces), ADR-017 (auth), ADR-024 and ADR-026 (tables in the tree), ADR-032 (the published wiki), ADR-037 (trusted cairns), ADR-038 (cross-Cairn links as edges), ADR-039 (citations as JSON-LD), PRD principle 6 (bridges between Cairns)

## Context

The roadmap's "'Cited by', across Cairns" asks the other direction of ADR-038 and ADR-039: not this Cairn naming its own sources, but this Cairn learning that another page, somewhere else, names one of its pages as a source. ADR-038 gave every published page a canonical address, `<origin>/w/<id>`. ADR-039 gave that address something to be linked as: a `citation` or `isBasedOn` entry in another Cairn's own JSON-LD. Nothing today tells the cited Cairn that link exists. It would have to be told, by whoever made it, or go looking for every address that might mention it, which nothing in Cairn's design supports and which ADR-037 explicitly ruled out doing through a shared registry.

Webmention (https://webmention.net) is the existing, small, well-specified protocol for exactly this: a page that links to another notifies the linked page's site, by sending its own address (`source`) and the address it links to (`target`) to a receiving endpoint, which then fetches `source` and confirms the link is really there before trusting the notice. It asks for no new protocol design, and it is a natural fit for the published wiki (ADR-032), which already serves pages at stable, public addresses for exactly this purpose.

Accepting a Webmention notice means the server fetches an address an anonymous caller supplies, which nothing in Cairn does today. `packages/api/src/oauth/providers.ts` already fetches identity providers from the server, but only for the owner's own sign-in; that fetch's destination is fixed by the server's configuration, not by the request. A `source` URL here comes from whoever posts the notice, so verifying it means a genuinely new kind of outbound request: server-side request forgery (SSRF) becomes a real risk for the first time, since a caller could name an internal address, a cloud metadata endpoint, or anything else reachable from the container, and use the citation notice as a probe or worse.

Who to believe once `source` genuinely does link to `target` is a separate question from whether it does. ADR-037 already gives every Cairn a "Trusted cairns" table: an address on that list has already been checked to be a real Cairn, once, by the owner's own `cairn trust`. That is a reasonable bar for showing a citation to visitors without a person looking at it first. An address not on the list might still be telling the truth, but nothing here vouches for it, so it should wait for the owner, the same way any other new fact about a page can wait for review without blocking the write.

## Decision

1. **`POST /webmention`, a new route on the published wiki's no-auth surface (ADR-032, alongside `/w`, `/sitemap.xml`, `/.well-known/cairn.json`).** It takes `source` and `target` as form-encoded fields, the shape the Webmention spec uses. `target` must resolve to a page this Cairn currently publishes, addressed exactly as ADR-038 shapes it (`<origin>/w/<id>`); anything else is answered `400` naming what was wrong (not this origin, not a published page, not a page at all) and what to check. A notice that passes moves to verification.

2. **Verification fetches `source` and confirms it links to `target`.** The fetch runs through a new SSRF-safe helper (`packages/api/src/citations.ts`, the one place in this Cairn a request goes out at an anonymous caller's direction): http or https only, the hostname resolved and checked against loopback, private, and link-local ranges before connecting (resolved, not string-matched, so a DNS answer chosen to defeat a hostname check is still caught), a bounded timeout and response size, and redirects capped and re-resolved at each hop rather than followed blindly. `source`'s body is scanned for an anchor whose `href`, resolved against `source`, equals `target`. No link found, or the fetch fails for any reason, and the notice is refused with the reason, the same discipline `cairn check-sources` (ADR-036) and `cairn trust` (ADR-037) already follow toward addresses outside this Cairn.

3. **A verified notice is a row in a new "Citations" table**, lazily created the first time one is needed, the same trick ADR-037 used for "Trusted cairns": no new port, no new schema. Fields: `page` (`relation`, target `pages`, the cited page), `source` (`url`, the citing address), `status` (`select`, `pending` or `accepted`). The row is upserted keyed by `page` and `source` together, so a repeat notice updates rather than duplicates.

4. **`status` is decided by whether `source`'s origin is in "Trusted cairns" (ADR-037) at the moment the notice is verified.** An origin on that list is `accepted` immediately, no person involved, the same way the owner's own `cairn trust` already stands in for them once. Any other origin is `pending`: stored, not shown, until the owner accepts it. Nothing new is built to review a `pending` row: the "Citations" table is an ordinary table the moment it exists, so `cairn tables`, `rows`, `row`, `upsert`, their MCP tools and REST endpoints, and the review console's existing `/t/:cid` and `/t/:cid/r/:rid` routes (ADR-009) already list it, open it, and let the owner edit `status` to `accepted` or delete the row, with zero new console, MCP or CLI code. Hard rule 14 holds the same way ADR-037 recorded it holding: nothing was added to one surface only, because nothing new was added to any surface for reading or managing the table.

5. **A published page (`/w/:id`) gains a "Cited by" section, listing only `accepted` rows for that page**, alongside its existing Sources section (ADR-027) and JSON-LD (ADR-039). A page with no accepted citations shows nothing new. `pending` rows are never shown on a published page; they exist only for the owner to find and decide on.

6. **The write path is REST-only, and this ADR is why.** A Webmention notice is not something an agent or the CLI ever originates; it arrives from another site's own software, over HTTP, in the shape the Webmention spec defines, which is not Cairn's shape to translate. Hard rule 14 is written for capability parity across surfaces Cairn itself exposes to its own clients; an inbound webhook from an unrelated protocol is not that. The read side, seeing which citations exist and their status, is not an exception at all: it comes from the same generic table surface every door already has, per point 4.

7. **`cairn export --format site` (ADR-035) is deliberately unchanged.** A static export is a folder of files with no server behind it once written; it cannot receive a `POST` at all, so there is nothing for this ADR to add there. A page in a static export keeps exactly the Sources and JSON-LD it already has (ADR-039), with no "Cited by" section, because a static copy cannot know what has been accepted since it was made.

## Consequences

1. One new module, `packages/api/src/citations.ts`, holding the SSRF-safe fetch, the link check, the "Citations" table helpers, and `receiveCitation`; one new route wired into `registerPublicWiki`; one new section in `public.tsx`'s page render. No new port, no new storage kind, no new MCP tool, no new CLI command.
2. This is the first place an anonymous, unauthenticated request causes the server to make an outbound fetch. The SSRF guard is the safety boundary for that, and it is written once, in one module, rather than trusted to be reimplemented correctly at each call site.
3. A citation from an untrusted address sits `pending` until the owner reviews it, which means a real citation can go unseen on the published page for a while. That is intentional: showing an unreviewed claim about who cites a page is a worse failure than a delay, and the owner already has, for free, the same table tools they use for everything else to clear the backlog.
4. `TRUSTED_TABLE_NAME` (`"Trusted cairns"`) is read by both `packages/cli/src/trust.ts` and the new `packages/api/src/citations.ts`, in different packages that must not import each other's runtime code (hard rule 16). The literal string is duplicated between them, with a comment at each site pointing at the other, the same pattern ADR-039 already established for `isCairnPageAddress`.
5. Still `later` on the roadmap: "Discovery by following citations", an agent or the CLI walking outward along `citation`, `isBasedOn` (ADR-039) and now accepted "Cited by" rows on its own. This ADR gives it a trustworthy set of inbound edges to start from; it does not build the walk.
