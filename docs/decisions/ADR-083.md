# ADR-083: A stopped local Cairn does not send commands to the cloud

Status: accepted

Date: 2026-11-10

Relates to: ADR-018 (scale to zero), ADR-029 (instances), ADR-082 (sync guard). Supersedes the failover part of ADR-029.

## Context

ADR-082 blamed a short `cairn sync --every` loop for the October bill. The owner replied that they almost never used Cairn, that the app woke and could not go back to sleep, and that sync needed trimming.

The registry on the owner's laptop lists `laptop` (localhost) first and `azure` second. ADR-029 sends every unnamed command to the first that answers. With the laptop server stopped, which is its usual state, every `cairn` command from any agent session (the skill, the session hook) went to Azure. Each woke it and restarted the 30 minute idle timer. One command every few minutes keeps a replica up all day, which matches the metrics: awake around the clock, about one request per six minutes. No logs exist to confirm the caller.

Options: (a) keep the failover and warn; (b) stop failing over to cloud instances unless named; (c) shorten the idle time.

## Decision

1. After an instance on this machine fails to answer, instances not on this machine are not tried for an unnamed command. The error names the stopped one, says the cloud one was not tried and why, and gives `cairn start` and `--instance <name>`.
2. With no instance on this machine registered, cloud instances are tried in order, as before.
3. `cairn sync`, `cairn start`, `--instance` and `CAIRN_URL` are explicit and still reach the cloud.
4. The session hook (`overview --brief`) already prints one line and exits 0; it now does so instead of waking Azure.
5. The guard of ADR-082 stays.

## Consequences

1. An idle laptop plus agent chatter no longer bills Azure.
2. The cloud is no longer an automatic standby for the CLI. Away from the laptop, name it once with `--instance azure` or set `CAIRN_URL`.
3. Option (c) is left alone: 30 minutes is the documented trade-off (ADR-018).
