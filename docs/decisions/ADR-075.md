# ADR-075: Templates and daily notes are pages with a shape

Status: accepted

Date: 2026-09-23

Relates to: ADR-024/ADR-026 (a collection is just a page with no parent), ADR-037/ADR-040/ADR-064 (well-known tables, the precedent this follows for well-known page collections), hard rule 14 (a capability added to one surface is added to the others)

## Context

`docs/ROADMAP.md` named this in one line: "Templates and daily notes are pages with a shape." Checked with the owner, three things were decided before writing this ADR: a template is an ordinary page, living under a designated "Templates" collection, with no new field or store; creating a page "from a template" copies the template's body and substitutes a small fixed set of placeholders, not a templating language; and a daily note is created on demand only, no scheduler, under a designated "Daily notes" collection.

Cairn has no notion of a "well-known collection" today, but it already has the equivalent for tables: `ATTACHMENTS_TABLE_NAME`, `CITATIONS_TABLE_NAME` and `TRUSTED_TABLE_NAME` (ADR-064, ADR-040, ADR-037) are each a fixed name, found by listing and matching, created the first time the feature is used. The same technique carries over to pages: a collection is just a root page (ADR-024/ADR-026), so "the Templates collection" is a root page named `Templates`, found the same way.

Page creation itself has no shared `operations.ts` function today (unlike every other write): MCP, REST and the CLI's server side all call `context.pages.create` directly with the same shape. "Create from template" is new cross-surface logic, not a thin wrapper on an existing one, so it belongs in `operations.ts` from the start, per hard rule 14's own reasoning.

## Decision

1. **Well-known collections**: `TEMPLATES_COLLECTION_NAME = "Templates"` and `DAILY_NOTES_COLLECTION_NAME = "Daily notes"` (`packages/api/src/templates.ts`, new module). Each is a root page (`parentId: null`), found by listing root pages and matching `title`, created empty the first time it is needed, exactly the pattern `ensureAttachmentsTable` and its siblings already use for tables. A page a person names exactly `Templates` or `Daily notes` at the root collides with this, the same accepted risk the existing well-known tables already carry.
2. **Placeholders**: `{{date}}` and `{{title}}`, substituted by plain string replacement (`replaceAll`), no loops, conditionals or nested syntax. `{{date}}` is today's date, **date-only**, `YYYY-MM-DD`, deliberately not the full ISO timestamp `toISOString()` gives elsewhere in this codebase (`verifiedAt`, `edited_at`): a daily note needs day granularity to find "today's note" again later, and a timestamp would never match on a second lookup the same day. `{{title}}` is the new page's own title, so a template can put it in a heading. Anything else in a template body (`{{foo}}`) is left untouched; there is no third placeholder to add without a new ADR.
3. **`createPageFromTemplate(context, { templateId, title, parentId }, by)`** (`packages/api/src/operations.ts`): loads the template page, substitutes both placeholders into its body, creates a new page with that body under `parentId` (default: wherever the template itself suggests, or the workspace root). Wired to all three surfaces per hard rule 14: MCP tool `create_page_from_template(template_id, title, parent_id?)`, REST `POST /pages/from-template`, CLI `cairn new --template <id> --title "..." [--parent <id>]`. Browsing available templates needs no new tool: the Templates collection is an ordinary page tree, already reachable with the tree-walking tools every surface already has.
4. **`getOrCreateDailyNote(context, by)`** (`packages/api/src/templates.ts`): finds or creates the Daily notes collection, looks for a child page titled today's date (`YYYY-MM-DD`, UTC), and returns it if found. If not found, creates it: from the page titled `Daily note` inside the Templates collection if one exists (substituting `{{date}}`/`{{title}}` as usual), or with an empty body otherwise. Wired to all three surfaces: MCP tool `get_today_note()`, REST `POST /pages/daily-note`, CLI `cairn today`. `POST`, not `GET`, since the first call of the day writes.
5. No new page field, store method, or index. The conformance suite (hard rule 2) is unaffected.

## Consequences

1. An agent or a person scaffolds a page from a reusable shape, or opens today's note, without any new storage: both features are ordinary pages the moment they exist, so they sync, export, search and version exactly like any other page, for free.
2. Daily notes are UTC-day granularity. A note made late in the evening in CET can land under what already reads as "tomorrow" in UTC for a few hours around midnight CET. Documented as a known limitation, not fixed here: fixing it needs a time zone setting this project does not have, and the roadmap item did not ask for one.
3. Placeholder substitution is deliberately minimal. A template that wants more (a variable beyond date/title, a conditional section) is out of scope; if asked for, it is a new ADR, not an extension slipped in here.
4. `{{date}}`'s date-only format is a new convention alongside the existing full-timestamp one; anyone reading a template body needs to know which one a given `{{date}}` occurrence resolves to, since this ADR gives it only one meaning, day-granularity, everywhere it appears.
