# ADR-055: The workspace summary gets its own budget, not the leftovers

Status: accepted, amends ADR-012
Date: 2026-09-16

## Context

ADR-012 decided that the MCP server instructions carry a live summary of the workspace: its tables, its top-level pages and its common tags, so that an agent reading the instructions at initialize knows what this Cairn can answer. That is the whole reason a client should reach for Cairn before answering from memory.

On a real workspace it does not happen. A live initialize against the owner's laptop copy, which holds 104 pages and 2 tables, returned this as the entire summary:

```
Pages: 104. Collections (top-level pages):
- and 2 more collections
Common tags: "peptide"
```

Not one collection is named. The tag list is a single tag. An agent reading that learns the workspace is large and nothing about what is in it, which is the opposite of the decision's intent.

The cause is arithmetic. `packages/api/src/mcp/instructions.ts` sets `INSTRUCTIONS_BUDGET` to 2200 characters for the whole text, and `buildInstructions` gives the summary whatever is left after the fixed instructions: `INSTRUCTIONS_BUDGET - SERVER_INSTRUCTIONS.length - 2`. The fixed text is 1895 characters. The summary therefore gets 303, and `fitLines` spends most of that on headings before the tag reserve, `Math.min(200, Math.floor(room() / 3))`, takes a third of what is left. The live response was 2185 characters, so the ceiling was not even reached: the layout ran out of room long before the budget did.

The failure was invisible for four days because the tests build a summary for a small workspace, where 303 characters is plenty. The summary degrades exactly as the workspace becomes worth summarising.

The CLI's `overview` command shows the collections correctly, because it uses a larger budget. So the summary builder works. Only its allowance is wrong.

Two options were weighed. Raising the total ceiling alone was rejected as insufficient on its own, because the remainder arithmetic would still let any future edit to the fixed text silently eat the summary again. Cutting the fixed text alone was rejected for the same reason in reverse. The allowance has to stop being a remainder.

## Decision

1. **The summary has a floor, not a remainder.** `SUMMARY_BUDGET` is 700 characters and is guaranteed to the summary regardless of how long the fixed instructions are. The summary is built to its own budget and the fixed text is checked against the space that remains, which is the reverse of today.

2. **The fixed instructions have a ceiling of 1500 characters, enforced by a test.** The current text is 1895 and must be cut. Anything the skill file in `skills/cairn/` already says in full is said shorter here, because the skill is where the long form belongs. A change that pushes the fixed text over 1500 fails the build rather than quietly shrinking the summary.

3. **The total ceiling rises to 2400 characters, about 600 tokens.** This is a real cost paid at every initialize by every client, and it is the cost ADR-012 was always asking for. `pnpm context-cost` is run and the README numbers updated in the same commit, per the documentation rule on instruction text.

4. **A section that cannot show at least three items is dropped, not truncated to a stub.** "and 2 more collections" with nothing before it is worse than no line at all, because it spends characters to say nothing. The same applies to a tag line carrying a single tag.

5. **The summary spends its budget on names before counts.** Collections are listed by name, most pages first, each with its page count. The overall page count is one short line. If the budget runs out, the trailing "and N more" appears only after at least three collections have been named.

6. **The test builds a summary for a workspace the size of a real one.** A hundred pages, a dozen top-level collections with long names, two tables and twenty tags. It asserts that at least three collections are named, that the tag line is either absent or holds at least three tags, and that the total stays within the ceiling. A test that only ever sees a small workspace cannot see this defect and is the reason it shipped.

## Consequences

1. An agent that connects to a real Cairn learns what it holds, which is what ADR-012 decided and has not delivered since it was written. ADR-012's decisions stand; only the allowance changes.

2. Every session pays about 150 more tokens at initialize. That is the trade ADR-012 accepted in principle, now paid in fact, and it is small beside the cost of an agent answering from memory because it did not know the workspace held the answer.

3. The fixed instructions must get shorter, and shorter text is harder to write than longer text. The 1500 character ceiling is deliberately tight so the pressure stays on the fixed half rather than on the live half.

4. The rule that the MCP instructions, the summary and the skill must say the same things still holds, and this decision makes the skill carry more of the weight. The three are checked together when any of them changes.

5. Still open: the summary is cached for 60 seconds and rebuilt on demand. On a very large workspace, building it may become slow enough to matter at initialize. Nothing observed yet, and the cache is what would need to change.

## Relates to

ADR-012 (the live workspace summary, amended here), ADR-011 (Cairn tells clients when to use it), ADR-053 (making Cairn present in a session at all).
