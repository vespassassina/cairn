# ADR-034: A public Cairn describes itself at /.well-known/cairn.json

Status: accepted
Date: 2026-09-14
Relates to: ADR-032 (the published wiki), PRD principle 6 (bridges between Cairns)

## Context

ADR-032 gave Cairn a published surface at `/w`, readable with no sign-in and indexed by search engines. The owner's direction of 2026-09-14 looks past that to a registry of public Cairns, so a person or a crawler can find one Cairn from another: "we are not going to be islands with no bridges". The roadmap's "Bridges between Cairns" section lays out that path, and every item on it, a registry, discovery by following citations, "cited by" notices, needs one thing first: a place a Cairn says what it is, in a form a machine can read without guessing at HTML.

`/w` already answers "what pages does this Cairn publish". It does not answer "what is this Cairn, in one sentence", "who is it, in whose voice", or "what does it cite". Those are facts about the Cairn as a whole, not about any one page, and there is nowhere on the published surface to put them.

## Decision

1. **A JSON file at `/.well-known/cairn.json`, on the published surface, no sign-in needed.** It follows RFC 8615 (well-known URIs), the convention `/.well-known/oauth-authorization-server` already uses in this codebase (ADR-017).

2. **Its shape:**

   ```json
   {
     "cairn": "1",
     "name": "…",
     "description": "…",
     "language": "en",
     "licence": "CC BY 4.0",
     "topics": ["peptides", "biohacking"],
     "collections": [{ "title": "Peptides", "url": "https://…/w/pg_…" }],
     "sitemap": "https://…/sitemap.xml",
     "cites": []
   }
   ```

   `cairn` is a small format version, so a later change can be read safely by an older client. `collections` lists the roots of the published subtrees, the same ones `GET /w` shows, each with its canonical address. `cites` is the Cairns this one's published pages cite; it is always empty today, because nothing yet tells a citation in `sources` (ADR-027) apart from a link to an ordinary web page. Filling it in is future work under "Bridges between Cairns" (`docs/ROADMAP.md`), not this ADR: shipping the field now, always empty, means a registry can start reading it without a second migration later.

3. **Name, description, language and topics are owner settings, not content.** They describe the Cairn, not a page in it, so they belong beside `CAIRN_CONTENT_LICENCE` in configuration: `CAIRN_NAME`, `CAIRN_DESCRIPTION`, `CAIRN_LANGUAGE` (default `en`), `CAIRN_TOPICS` (comma separated). None are required. `name` defaults to "Cairn" so the field is never empty; `description` and `topics` are omitted when unset rather than sent empty, so a reader can tell "not described" from "described as nothing".

4. **Nothing here decides how a registry works.** The registry itself, `cairn publish --register`, IndexNow notifications, and citation tracking are separate roadmap items, each needing its own ADR before code. This file is what they will all read.

5. **The published-wiki rule still applies.** The file is served by the same registration as `/w`, so it inherits the security headers and the sign-in bypass already scoped to that surface (ADR-032). It names no page that is not published, because `collections` is built from the same published set `/w` uses.

## Consequences

1. A public Cairn can be identified and described by a machine without scraping its HTML. This is the prerequisite every other discovery item on the roadmap names.
2. Four settings are added, all optional, none secret. `packages/cli/test/agent-guides.test.ts` requires each to be documented in `docs/AGENT-OPERATE.md`, so they are added there in the same commit.
3. `cites` ships empty. It is a promise about the shape of the file, not a working feature, and the ADR says so rather than letting the roadmap imply it already works.
4. A Cairn with nothing published still serves the file, with an empty `collections` array. There is no reason to 404 it: knowing that a Cairn exists and publishes nothing is itself an answer, and it costs nothing to say so.
