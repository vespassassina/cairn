# ADR-009: A server-rendered review console, styled with artifactkit

Status: accepted
Date: 2026-09-12

## Context

CLAUDE.md forbade frontend code until Phase 1 passes its gate, because of risk R5: building the editor first because it is fun.

But the MCP-first phase has a gap. Claude writes to Cairn directly (ADR-008), and the owner needs to see what it wrote and undo it, or the trust that makes MCP-first work never forms. That is a review need, not an editing need, and it belongs to Phase 1.

## Decision

### 1. A review console is allowed in Phase 1, with hard scope limits

What it does:

1. Recent changes as the home page: every write, newest first, with actor, page and change note, filterable to agents only.
2. Page view in read mode, with wiki links resolved to titles and broken links marked, a page tree, backlinks and last-changed metadata.
3. Edit as a plain Markdown textarea. A version conflict shows both versions instead of losing the edit.
4. History per page and per row: a timeline, a diff between versions, and restore.
5. Collections as a sortable table, with a row form generated from the schema.
6. Search and new page.

What it does not do, and must not grow into:

1. No rich editor. BlockNote stays in Phase 2.
2. No board, calendar or timeline views of collections (PRD non-goal 1).
3. No client-side application. Pages are rendered on the server and work with JavaScript off, apart from table sorting and the `/` search shortcut.

### 2. Rendered on the server by the same Hono app

Hono JSX, plain HTML forms, posts that redirect. It runs on every target without change and adds no build step (ADR-006). Route handlers stay on web standard `Request` and `Response`.

### 3. Styled with artifactkit

The owner's artifactkit provides the visual language: `theme.css`, `components.css` and `print.css` for layout, prose, pills, tables, timelines and form controls, and `core.js` for table sorting and keyboard navigation.

It is copied into the repo as a generated TypeScript module by `pnpm sync:artifactkit`, not read from `~/.claude/skills/artifactkit` at runtime. A serverless function has no home directory, and a runtime file read would break ADR-006. The generated file records the source path and date so a stale copy is visible.

Cairn-specific styles go in a separate small stylesheet that uses artifactkit's tokens only. No colour is hard-coded outside artifactkit's theme block.

### 4. Everything rendered is treated as untrusted

Agents write page content, and page content can carry injected markup. Markdown is rendered with raw HTML disabled, so any HTML in a page is shown as text, never executed. Link targets are restricted to http, https, mailto and internal page links.

### 5. Auth for the console

Dev mode: the owner enters the dev token once and gets an HttpOnly, SameSite=Strict session cookie. Every form post also checks the Origin header, so a page on another site cannot submit a form to the console. Under ADR-007 the console signs in through the same OIDC flow as MCP.

## Consequences

1. CLAUDE.md's frontend rule is narrowed: the review console is allowed, the Phase 2 editor is still gated.
2. R5 in the PRD gains a second mitigation: the console's scope limits above, checked in review.
3. The api package gains a JSX configuration and a markdown renderer dependency.
4. artifactkit changes reach Cairn only when someone runs the sync script, which is deliberate: a styling change should be a visible commit, not a silent runtime difference.
