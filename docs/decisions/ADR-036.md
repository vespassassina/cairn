# ADR-036: cairn check-sources reports dead links and recognises DOIs and PubMed ids

Status: accepted
Date: 2026-09-15
Relates to: ADR-013, ADR-023, ADR-027, ROADMAP "Bridges between Cairns" ("Citations kept correct")

## Context

The owner picked "Citations kept correct" off the roadmap: a job that checks each web source still answers, lists dead ones beside the stale pages (ADR-028), offers an archived copy where one exists, and recognises stable identifiers such as a DOI or a PubMed id as links.

`sources` (ADR-027) is a list of short strings on every page and row: a URL, or a citation such as "Smith 2021, J Pept Sci". Today only an `http(s)` string is shown as a link, in the console (`packages/api/src/web/console.tsx`) and the published wiki (`packages/api/src/web/public.tsx`). Nothing checks that a link still resolves, and a DOI or a PubMed id, both common in the peptide research the owner keeps in Cairn, renders as plain text even though each names an address as precisely as a URL does.

Two things needed a decision:

1. **Where the checking runs.** A server endpoint would mean Cairn reaching out to arbitrary addresses on a schedule, on behalf of every workspace, from wherever it is deployed, which the owner has not asked for and which no ADR has scoped (rate limits, outbound egress on Azure, who pays for the requests). `cairn sync` (ADR-023) already set the precedent for work that is a client of something outside Cairn, not a server feature: sync is a client of two Cairns, this is a client of the web.
2. **What counts as an address to check.** `isUrlSource` (ADR-027) only recognised `http(s)`. A DOI and a PubMed id are both stable identifiers with a canonical resolver (`doi.org`, `pubmed.ncbi.nlm.nih.gov`), so both are addresses a source can name without being a raw URL.

## Decision

1. **`cairn check-sources [--root PAGE] [--timeout MS] [--json]`**, a new CLI-only command, no server or MCP change (ADR-013 rule 9: a surface leaves out what it cannot express; nothing here needs the server). It reads pages through `/export/pages` and rows through `/tables/:id/rows`, the same endpoints `export` uses, so it needs no new REST route.
2. **Report only, in v1.** No new stored field, no write. The roadmap item asks to "list" dead ones, not to persist a status on every page; a page's own freshness is what `verified_at` (ADR-028) already tracks, and the two stay separate; a future ADR can persist a check result if the owner asks for one.
3. **`sourceHref(source)`, in `packages/core/src/sources.ts`,** replaces the boolean `isUrlSource` (kept, since the check for "is this a plain URL" is still useful on its own) as what the console and the public wiki call to decide whether a source is a link and where it points. It recognises, in order: an `http(s)` address as is; a bare or `doi:`-prefixed DOI (`10.\d{4,9}/...`), resolved to `https://doi.org/<doi>`; a PubMed id (`PMID: 12345678` or `pmid:12345678`), resolved to `https://pubmed.ncbi.nlm.nih.gov/<id>/`. Anything else returns `null` and renders as plain text, as before.
4. **The CLI duplicates `sourceHref` locally** (`packages/cli/src/sources.ts`), rather than importing it from `@cairn/core`: hard rule 16 keeps the CLI's runtime dependencies to `fetch`, Web Crypto and a short list of `node:` modules, and `@cairn/core` is a `devDependency` used only in tests. The static site export (`packages/cli/src/site-format.ts`, ADR-035) now calls this duplicate too, so a DOI or PubMed source is a link there as well as in the console and the public wiki, for capability parity (ADR-013 rule 14). The two copies are kept in step by running the same test cases against both (`packages/core/test/sources.test.ts`, `packages/cli/test/sources.test.ts`).
5. **Checking one address:** `HEAD`, falling back to `GET` when a server answers `405` to `HEAD` (some do not implement it), with a timeout (`--timeout`, default 10 seconds) and redirects followed. A `2xx`–`3xx` result (after redirects) is alive; anything else, including a network or timeout failure, is dead. Each distinct address is checked once even when several pages or rows name it.
6. **A dead `http(s)` address** is looked up against the Internet Archive's availability API (`https://archive.org/wayback/available?url=...`); the closest snapshot's address is reported when one exists. A DOI or PubMed address that fails is reported dead with no Wayback lookup: the identifier itself, not the resolver's current uptime, is what a citation should be checked against, and a future ADR can add a registry-specific check (Crossref for a DOI, NCBI's E-utilities for a PubMed id) if that turns out to matter more than reachability.
7. **The MCP instructions gain one clause** (`packages/api/src/mcp/instructions.ts`): "cite the original, not a summary of it", matching the roadmap wording, next to the existing sentence about naming where a fact came from. `packages/api/src/mcp/summary.ts` and `skills/cairn/SKILL.md` carry the same line (rule 8).

## Consequences

1. Nothing is written by `check-sources`; running it, or not, changes no stored data. It can be run as often as wanted, and on a schedule the same way `cairn sync --every` is, though this ADR does not add `--every` itself: that is a small follow-on if the owner wants it, not a new decision.
2. A workspace with many sources means many requests on one run; there is no batching or backoff beyond the per-request timeout. For a personal wiki of hundreds of sources this is seconds, the same scale `cairn sync` already reads in one run (ADR-023 consequence 2).
3. A DOI or PubMed source now renders as a link everywhere a source does: the console, the published wiki, and a static site export. Nothing else about how sources are stored, normalised or limited (ADR-027) changes.
4. Not done: persisting a check result on the record, a `--every` schedule for `check-sources` itself, checking a DOI or PubMed id against its own registry rather than only via reachability of the resolved address, and the wider "Links to the original, across Cairns" and "'Cited by', across Cairns" roadmap items, which need `sources` to distinguish a citation of another Cairn's page from an ordinary web link (ADR-034 consequence 3) and are left for their own ADRs.
