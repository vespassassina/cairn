# ADR-010: No sign-in for trusted local requests

Status: accepted
Date: 2026-09-12
Amends: ADR-009 rule 5 (console sign-in) and the dev-mode token in PRD section 7

## Context

Running Cairn locally meant setting `CAIRN_TOKEN`, passing it to Claude Code, and typing it into the console. On a server that only listens on loopback, the token protects against almost nothing a local user could not already do, and it got in the way enough that the console appeared broken.

Dropping auth for "anything that reaches localhost" is not safe, though. A web page open in the owner's own browser can send requests to localhost in two ways:

1. **DNS rebinding.** An attacker's domain is made to resolve to 127.0.0.1. The connection is local, but the browser sends the attacker's domain as the Host header.
2. **Cross-site requests.** A page on another site can make the browser post to `http://localhost:8787`. The Host is local, but the browser adds the page's Origin header and cannot be made to omit it.

## Decision

On a loopback server (dev mode already refuses any other bind address), a request needs no token when all of these hold:

1. **Local trust is on.** On by default. `auth.trustLocal: false` in `cairn.config.json`, or `CAIRN_TRUST_LOCAL=0`, turns it off.
2. **The Host header is a trusted local name.** `localhost`, `127.0.0.1` and `::1` always, plus any names listed in `auth.localHosts`. This defeats rebinding.
3. **For MCP, the request carries no Origin or a local one.** Claude Code and other non-browser clients send none. A request from a foreign page always carries one. This defeats cross-site requests.
4. **For console form posts, the Origin matches the console.** This check already existed (ADR-009 rule 5) and stays.

`CAIRN_TOKEN` becomes optional. When it is set, it still works for any host name outside the trusted list. When local trust is off, it is required, and startup refuses to run without it.

Settings move to an optional `cairn.config.json`, found by walking up from the working directory, with environment variables taking precedence. A relative database path in it is resolved against the file, not against wherever the server was started.

## Consequences

1. Local use is `pnpm dev`, then open `http://localhost:8787` or add the MCP server with no header.
2. Writes still name their actor: the owner for the console, an agent for MCP. Local trust changes who may connect, not how writes are attributed (ADR-008).
3. The trusted-host list is a security setting. Adding a name to it says that name only ever resolves to this machine.
4. None of this applies once Cairn is deployed. A non-loopback bind still refuses to start until the OAuth server from ADR-007 exists, and that server replaces this mechanism outside dev mode.
