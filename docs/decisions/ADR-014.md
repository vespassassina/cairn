# ADR-014: The CLI ships as an npm package and as standalone executables

Status: accepted
Date: 2026-09-12

## Context

The `cairn` command (ADR-013) must install on Windows, macOS and Linux, for people who may not have Node, or want it. Cairn is meant to be deployable by anyone, so installing its CLI cannot assume a JavaScript toolchain.

Options considered:

1. **npm package only.** One install command, works on every OS, and npm writes the Windows launcher itself. But it requires Node 22 or later.
2. **Node single executable applications.** Official, but each platform's executable has to be built from that platform's Node binary and injected with a separate tool, and the feature is still marked experimental.
3. **Bun `build --compile`.** One command builds an executable for every platform from any one machine. The executable carries the Bun runtime instead of Node's. The CLI only uses `fetch`, `parseArgs`, file reads and `process`, all of which Bun implements.
4. **Deno `compile`.** Similar to Bun, with a different module system to adapt to.
5. **Rewrite the CLI in Go.** Small executables, but a second language and a second copy of the client logic to keep in step.

## Decision

1. **Two ways to install.** The npm package, for anyone with Node 22 or later. Standalone executables, for everyone else, needing nothing installed.
2. **Executables are built with Bun, as a build tool only.** Cairn's server and tests run on Node; only the packaged CLI runs on Bun's runtime. The Bun version is pinned in `scripts/build-cli.mjs` and in CI, and fetched with npx when it is not installed.
3. **Five targets:** `linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, `windows-x64`. Linux builds are for glibc distributions; Alpine and other musl systems use the npm package. Windows on Arm runs the x64 build under emulation.
4. **Every build writes `SHA256SUMS`,** and the install guide shows how to check it on each OS.
5. **Each executable is run on its own OS before it ships.** CI at https://github.com/vespassassina/cairn/actions builds the CLI on Linux x64 and arm64, macOS and Windows runners, and runs `scripts/smoke-cli.mjs`: a real server, then the executable creating, reading, appending, searching and hitting a version conflict. A tag such as `v0.1.0` builds all five and attaches them to a GitHub release.
6. **The CLI's code uses only what both runtimes provide.** The unit tests run it on Node; the smoke test runs the compiled executable. A difference between the runtimes shows up there.
7. **Executables are not signed yet.** macOS and Windows warn about unsigned downloads. `docs/CLI.md` says what each warning looks like and how to get past it. Signing needs an Apple developer account and a Windows code signing certificate, which is a cost to decide on before the launch, not now.

## Consequences

1. Anyone can install the CLI by downloading one file. The guide covers each OS step by step.
2. The executables are large, 60 to 86 MB, because each carries a runtime. Accepted: it is one file, and it needs nothing else.
3. Two runtimes to keep in mind for the CLI. The smoke test is the guard, and CLI code stays inside the small set of APIs both support.
4. Until the repository is on GitHub with CI running, the Linux and Windows executables are built and checked for format but not yet run. The macOS ones were run on the machine that built them, the Intel one under Rosetta.
5. Signing and notarisation stay open, on the launch checklist.
