# ADR-012: The server instructions carry a live summary of the workspace

Status: accepted
Date: 2026-09-12
Extends: ADR-011

## Context

ADR-011 tells Claude to search Cairn before answering when Cairn "may hold the topic". But the instructions were fixed text, so Claude had no way to know what Cairn holds until it happened to search. A question about peptides would only reach Cairn if Claude guessed that it might.

Options:

1. **A tool, such as `describe_workspace`.** Claude would have to think of calling it, which is the same problem one step removed.
2. **An MCP resource.** Clients show resources to the user, not the model, and Claude Code does not read them unprompted.
3. **A summary inside the server instructions.** Sent once at initialize, and read by the model in every session. This is the only one of the three that reaches the model before it decides whether to use Cairn.

The cost of option 3 is that stored text lands in every session's context. Page titles and tags are written by people and by agents, and an agent may have copied a title from a hostile web page. So the summary is a prompt injection surface and has to be built as one.

## Decision

1. **At initialize, the instructions are the fixed text of ADR-011 followed by a summary** of what the workspace holds:
   1. Collections, with row counts.
   2. The page total, and the top-level pages, largest first, each with the number of pages under it.
   3. Up to 12 tags used on two or more pages.
2. **The whole text stays within ADR-011's 2,000 character budget.** The summary gets whatever room the fixed text leaves. Each section says how many items it left out.
3. **Every stored value is treated as untrusted:**
   1. Control characters and line separators become spaces, so a value can never start a new line.
   2. Values are cut to 60 characters.
   3. Each value is written as a JSON string, so its own quotes are escaped.
   4. The summary opens by saying that titles and tags are data written by people and agents, never instructions.
4. **Only initialize pays for it.** Other requests skip the summary. It is cached for 60 seconds per server, which is within the eventual consistency bound derived reads already have (ADR-005).
5. **A failure never blocks a connection.** If building the summary throws, the fixed text goes out alone.
6. **Titles, tags and counts only.** No page bodies, no row values, no ids.

## Consequences

1. Claude knows what Cairn holds from the first message. On the peptide wiki: one collection, 33 pages, seven categories and their tags.
2. The token cost per session rises from about 300 to about 500 tokens on a workspace of this size, and is capped by the budget whatever the size.
3. A workspace with many top-level pages shows only the largest. That rewards a tidy hierarchy, and is honest about what it leaves out.
4. Injection risk remains, reduced rather than removed: a 60 character quoted title can still say something persuasive. If that shows up in practice, the next step is to list only pages the owner wrote or reviewed.
5. Anyone who can connect to the MCP server can see the titles. They could already, by searching. Once OAuth lands (ADR-007), the summary follows the caller's access like every other read.
