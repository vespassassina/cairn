# ADR-032: A collection can be published, read-only and without sign-in

Status: accepted
Date: 2026-09-14
Amends: ADR-017 (every request needs sign-in)
Relates to: ADR-009 (the console), ADR-013 (three surfaces), ADR-023 and ADR-029 (sync), PRD principle 6 (bridges between Cairns)

## Context

ADR-017 made every request need sign-in. That is right for a private store, and it is what a Cairn holding someone's own notes needs.

The owner's direction of 2026-09-14 asks for the other half: Cairn as a knowledge manager and also a free knowledge source, with a wiki that people and search engines can read. The peptide wiki is the example. Nothing about it is private, and it is worth more read than hidden.

Several roadmap items wait on this one: the static site export, machine-readable citations on public pages, a Cairn that describes itself, and the registry that finds public Cairns by following citations.

The risk is the whole point of the feature. A mistake here does not lose data, it publishes it. So the decisions below are shaped by what must never happen: a private page readable by anyone, or a private title, id or link leaking through a public page.

## Decision

1. **Publishing is per page, and runs down the tree.** A page carries `public`. Marking a page public publishes it and every page under it, so marking a collection publishes the wiki beneath it. A page is published if it or any of its ancestors is public. Nothing is public until someone says so: `public` is false on every page, including every page that exists today.

2. **The published wiki is a separate, read-only surface at `/w`.** `GET /w` lists the published collections, `GET /w/<page-id>` serves one page, and both need no sign-in. They are HTML, server-rendered like the console, with a title, a description and a canonical address, plus `/sitemap.xml` and `/robots.txt` so search engines index them. Nothing else changes: every console route, REST, MCP and the CLI still need sign-in exactly as before.

3. **The published surface reads published pages and nothing else.** It never reads a page that is not published, whatever the address asks for: an unpublished id answers 404, the same answer as an id that does not exist, so the 404 tells an outsider nothing. There is no search, no history, no list of all pages, and no tables on it. A link to an unpublished page renders as plain text, never as a link, and the child list on a page shows published children only.

4. **It says nothing about who wrote what.** Actor labels name people and agents, so the published page shows the text, its sources and when it was last updated, and no actor, no change notes, no versions.

5. **Publishing is the owner's action, never an agent's.** The console has the control, the CLI has `cairn publish` and `cairn unpublish`, and REST carries `public` on a page. MCP does not: an agent writing a page must not be able to publish it, and hard rule 14 is answered here rather than by adding the tool. An agent asked to publish something tells the person to do it in the console or run the CLI command.

6. **Being published belongs to the server, not to the content.** `public` never travels with sync, export or import. A laptop copy of a published wiki is private until that copy is told otherwise, which is what someone syncing a public wiki to a laptop expects, and it means a sync can never publish anything.

7. **The published wiki carries the licence the owner chooses.** A published page shows the workspace's content licence when one is set (`CAIRN_CONTENT_LICENCE`), which is the owner's choice and separate from the licence of Cairn's code.

## Consequences

1. ADR-017's rule now reads: every request needs sign-in, except `/health`, the sign-in routes themselves, and the published wiki at `/w`, `/sitemap.xml` and `/robots.txt`, which serve only pages an owner has marked public.
2. Tests hold the line the feature lives or dies on: an unpublished page is 404 to a stranger, a private child never appears, a link to a private page is not a link, and no actor name reaches the page. A leak is a bug of the first order, with a `docs/LESSONS.md` entry.
3. Publication is computed by walking a page's ancestors, and the published index reads every page to find the published ones. That is fine at a few thousand pages and will need an index or a stored flag before it is fine at a hundred thousand.
4. Sitemaps list every published page. A very large published wiki will need the sitemap index format, which this does not implement.
5. Because `public` does not sync, a person who publishes on the laptop and expects Azure to serve it will be surprised. The console says so where the control is, and `docs/AGENT-OPERATE.md` says it too.
6. Nothing here shares a page with a named person: that is still PRD P2 item 6, and a different decision.
