# ADR-081: The console gains what a person needs to write notes, inside ADR-009

Status: proposed

Date: 2026-09-24

Relates to: ADR-009 (the console's limits), ADR-075 (templates and daily notes, whose UTC-only date this fixes), ADR-057 (search results by page), ADR-065 (diagrams, accepted and unbuilt, left out here), hard rules 14, 17, 19. Spec: `docs/specs/console-for-notes.md`.

## Context

The product review of 2026-09-24 found the console good at reviewing agents' writing and thin for a person writing their own: no preview while editing, no callouts or checklists, no Today, templates unreachable from the New page, a home page built for a first-time visitor, and delete, move and table creation missing from the console although every other surface has them. The owner wants Cairn for notes too, and asked for the preview to be upgraded.

Options for the preview: (a) a rich editor, rejected by ADR-009 and the PRD's Phase 2; (b) a preview page after submit, which exists and loses the editing context; (c) a preview column beside the textarea, refreshed by a button and, with script, on pause, chosen by the owner.

Options for "today": ADR-075 chose UTC and named the CET midnight problem as a known limitation because no time zone setting existed. A person writing daily notes at 23:30 CET hits it nightly.

## Decision

1. **Preview beside the editor.** The edit form is two columns on wide screens; the Preview button posts `preview=1` and re-renders with the draft intact. With script, a pause of 800 ms fetches `POST /p/:id/preview`, the same route, and swaps the column; Cmd+Enter or Ctrl+Enter submits. The script is a few lines in the existing `console.js`; nothing depends on it.
2. **Three Markdown extensions** in `packages/api/src/web/markdown.ts`, written as small in-house rules rather than plugins unless a plugin is clearly smaller and MIT: GitHub-style callouts (`> [!NOTE]`, `[!TIP]`, `[!WARNING]`) as `<aside class="ak-callout ...">`; toggles as `::: details Title` to `:::` rendered as `<details><summary>`; task lists `- [ ]` and `- [x]` as checkboxes carrying `data-line`. Raw HTML stays off. One renderer serves the console, the public wiki, the static export's server-side twin and the preview.
3. **Tickable checkboxes.** On the page view each task item is a small form posting `POST /p/:id/tick` with `line` and `version`; with script the checkbox submits on change, without it a "Save ticks" button appears. The server flips that one line and writes a revision noted `Ticked: <text>` or `Unticked: <text>`; a stale version shows the usual conflict page.
4. **`CAIRN_TIME_ZONE`**, an IANA name, default `UTC`, decides what "today" is for the console's `/today`, `cairn today` and `get_today_note` alike. Described in `docs/AGENT-OPERATE.md` (hard rule 19). Existing daily notes are not renamed; a switch may leave two notes around one midnight, documented. `[[YYYY-MM-DD]]` in a body resolves to that day's note when it exists.
5. **Template picker** on `/new`, "Blank" first, calling `createPageFromTemplate` (ADR-075).
6. **Owner home** at `/` when signed in: today's note, Inbox and review counts (ADR-078, ADR-079), the last ten changes, the five stale pages with most inbound links, the collections. "Connect an agent" folds into a `<details>` open only when no agent has written yet.
7. **Delete, undelete, move and table creation** in the console, each calling the operation the other surfaces already use (hard rule 14), with the parity test extended to the console. The action row folds Publish, PDF, Print and History under "More" on narrow screens through CSS only. Freshness sorts never-verified pages by inbound links, then age.
8. **Not here.** Link by title, embeds and page properties change contracts and get their own ADRs; Mermaid stays with ADR-065; no board, calendar or timeline views.

## Consequences

1. A person can write a day's notes in the console without missing a rich editor for the common cases: see what they write, tick things, start from a template, land on a page about their day.
2. The public wiki and the static export render the three extensions too, so published pages gain them for free and must be checked for them.
3. The preview fetch is the second progressive script after table sort (ADR-009 amended by ADR-080 to list it). Every path still works without it.
4. A new setting, `CAIRN_TIME_ZONE`, with a documented one-time seam around the day it is set. ADR-075's consequence 2 is closed by it.
5. The console catches up with the other surfaces on delete, move and tables, and the parity test now watches all four, so hard rule 14 stops being a rule the console is exempt from in practice.
