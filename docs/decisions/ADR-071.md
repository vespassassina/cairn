# ADR-071: ADR-070's "three note shapes" was wrong; there are two, and that's complete

Status: accepted

Date: 2026-09-23

Relates to: ADR-070 (amended by this one), ADR-060 (delete protection)

## Context

Building ADR-070, the note-matching turned out narrower than its Context section claimed. ADR-070 said `apply()` writes `Sync conflict:` "in one of three fixed shapes, whether the whole record, a merged document with N parts, or a deleted-and-recreated record." Reading `packages/cli/src/sync.ts`'s `note()` and `plan()` closely: only two shapes carry the substring, the whole-record replace and the N-part merge. A deletion never does, whether it's an ordinary propagated delete (`action.op === "delete"`, note: "Synced from X, where it was deleted") or `verifyDeletes`'s recreate-instead-of-delete path (ADR-060), which sets `conflict: false` outright.

This is not a gap. Tracing `plan()`: `conflict` is only ever set `true` in the branch where both sides changed a record's content since the last sync, and in that branch `source` (the write's payload) is never `null`, so the resulting action's `op` is always `"put"`, never `"delete"`. A delete action's `conflict` field is `false` by construction, every time, because deleting one side against an unchanged other is never itself a case of "both sides changed it differently" (ADR-030's own definition of a conflict). `verifyDeletes`'s recreate case is a related but separate thing: an unprovable deletion, reported as a `warning:` in the sync report, not folded into `conflicts` there either (see `packages/cli/test/sync-system.test.ts`'s ADR-060 scenarios, which assert on `warning:`, never on `conflict:`, for exactly this path).

## Decision

ADR-070's Context sentence claiming three note shapes is wrong; there are two, and they are exhaustive for what ADR-030 calls a conflict. No code changes: `packages/api/src/web/console.tsx`'s `/changes?conflict=1` and `adapter-sqlite`'s `note LIKE '%Sync conflict:%'` filter, both built as specced, already match every revision where `action.conflict` was true. Nothing was missed.

ADR-070's Decision, its consequences, and the built feature are unaffected and not superseded; only its Context's shape count was inaccurate, corrected here per this project's own rule that a wrong fact is not edited away.

## Consequences

1. A deletion, provable or not, never appears in the console's "Sync conflicts" list. That is correct: a deletion is never a two-sided conflict in this codebase's model, and an unprovable one is already visible as a `warning:` line on `/changes` and in the sync report's own output, a separate, already-existing concern.
2. `docs/specs/sync-conflicts-console.md`'s scope is unaffected: acceptance criteria 1 through 7 describe filtering on the note substring, not on a shape count, and all pass as built.
