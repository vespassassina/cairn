# ADR-013: One core, three surfaces: MCP, REST and a CLI

Status: accepted
Date: 2026-09-12
Refines: ADR-001 (the agent is the primary client; MCP becomes one of its doors, not the only one)

## Context

Cairn's positioning is "a wiki and tables your agents can write to, with every change reviewable". Until now the only way in for an agent was MCP.

MCP has a cost that every session pays. A client loads every tool's name, description and input schema when it connects, whether or not the session uses Cairn. Twelve tools and the server instructions come to a few thousand tokens. The most common complaint in Hacker News threads about agent memory tools is that they cost more context than they save.

Clients differ in what they can do:

1. **claude.ai, Claude Desktop, Cowork** have no shell. MCP is their only door.
2. **Coding agents** (Claude Code, Codex, Cursor) have a shell already. A command-line tool costs them nothing until they run it, and a skill file costs a one-line description until it is needed.
3. **Scripts, cron jobs and other agents** want plain HTTP, and a way to ask what changed since they last looked.

The core services already hold all the domain logic. What each surface adds is only translation.

## Decision

### 1. Three surfaces over one core

1. **MCP** at `/mcp`, as today.
2. **REST** at `/api/v1`, on the same Hono app.
3. **A `cairn` CLI**, a thin HTTP client for the REST API, plus a skill file that tells a coding agent when and how to use it.

Every capability is on every surface unless the surface cannot express it. The logic that surfaces share, such as edit modes, section replacement, error mapping and the shape of a page or revision, lives in one module that both MCP and REST call. A surface translates; it never decides.

### 2. The REST shape

1. Resources: pages, collections, rows, revisions, search, and changes.
2. JSON in and out. `GET /api/v1/pages/:id?format=markdown` returns the body as `text/markdown`, which is the cheapest read for an agent.
3. **Version tokens are ETags.** A read returns `ETag`. `PATCH` and `DELETE` must send `If-Match`; without it the answer is 428. A stale `If-Match` is 409 with the current version and content, exactly as MCP's `version_conflict`. A wildcard `If-Match: *` is refused, because it would skip the check. `PUT` on a row without `If-Match` only creates: if the row exists, it is a 409 that says which version to send.
4. Errors: 400 bad input, 404 not found, 409 conflict, 422 validation with every bad field named, 428 missing precondition. The body is `{ error, message, ... }` with the same codes MCP uses.
5. Lists page with `limit` and `cursor`.
6. The path carries a version, `/v1`, because a public API is a contract, and the MCP tools can change faster than scripts written against HTTP.

### 3. Auth and attribution are the same as MCP

1. The same check guards `/mcp` and `/api`: trusted local requests need no token (ADR-010), including the rule that a request with a foreign `Origin` is refused. Anything else needs the token, and OAuth replaces both later (ADR-007).
2. No CORS headers. The API is not for pages on other sites.
3. REST writes are agent writes, labelled with the caller's `User-Agent`. The CLI sends its own name and version. The owner's own writes still go through the console until OAuth gives callers a real identity. A write takes the same optional `change_note`.

### 4. A changes feed

`GET /api/v1/changes?since=<time>` lists revisions newest first, optionally only by agents or only by people. `since` is inclusive, so a client that stores the newest time it saw never misses a change made in the same millisecond, and drops the duplicates by version. The response's `newest` is the value to pass next time; take it from the first page when paging back with `cursor`. Changes made in the same millisecond have no defined order. It is eventually consistent, like every list (ADR-005).

This is what "shared between agents" means in practice: a second agent, a script or another machine asks what changed instead of searching again.

### 5. The CLI and the skill

1. The CLI talks HTTP only, never to the database file, so it works the same against a local server and a deployed one. `CAIRN_URL` picks the server.
2. Output is compact text by default, because the reader is usually an agent paying per token. `--json` gives the full API response for scripts.
3. Output is untrusted text, like any MCP result. The skill says so.
4. The skill file ships in the repo. Its description is the only part a client loads up front; the rest is read when Cairn is relevant.
5. `cairn append` may run without `--version`: the CLI reads the current version, appends, and on a conflict retries once on the newer version. The server still checks the version every time. This is allowed for append alone, because appending never overwrites anyone's text. Every other edit needs the version the agent read.
6. `GET /api/v1/overview` returns the same workspace summary MCP clients get at initialize (ADR-012), with a larger budget, so `cairn overview` answers "what is in here" in one call.

### 6. Which door to use

Coding agents with a shell should use the CLI. Everything else uses MCP. The README states the context cost of each. The characters are measured from what the server actually sends; tokens are estimated at four characters each, the rule the tool budgets already use. An exact count needs a tokenizer for each model, and is not worth a dependency for a comparison this lopsided.

## Consequences

1. Two surfaces to test instead of one. REST gets contract tests with realistic payloads, like the MCP tools (CLAUDE.md verification step 3).
2. The MCP tool descriptions, the server instructions and the skill must say the same things. A change to one is checked against the others.
3. The `/v1` API is a promise. Breaking it needs `/v2` and a changelog entry.
4. The cost comparison is a claim in the README, so it must be measured and repeated when tools change. `pnpm context-cost` does it. First measurement, on the peptide wiki: MCP costs about 2,700 tokens per session (2,228 for the 12 tool schemas, 453 for the instructions and summary). The CLI's skill description costs about 115, and its body about 724 more only in sessions that use Cairn.
5. ADR-001 still holds in spirit: the agent is the primary client, and the web UI comes second. What changes is that MCP is no longer the only way an agent gets in.
