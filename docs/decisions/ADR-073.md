# ADR-073: Stale-page reviews reach MCP, REST and the CLI, not just the console

Status: accepted

Date: 2026-09-23

Relates to: ADR-028 (verified_at and the console's Freshness screen), ADR-011 (server tells clients when to use it), hard rule 14 (a capability added to one surface is added to the others)

## Context

`docs/ROADMAP.md` named "Stale-page reviews: a regular list of the pages verified longest ago (ADR-028), with a re-check drafted by an agent for the owner to confirm." ADR-028 already built the list, the console's `/freshness` screen, never-verified pages first, then oldest-verified, but that screen is HTML for a person's eyes. An agent (the primary client, ADR-001) has no way to ask for the same ordering: `get_page` and search hits carry a page's own `verified_at`, but nothing lets an agent ask "which pages need a re-check", short of walking every page in the workspace itself.

"Drafted by an agent for the owner to confirm" was checked with the owner: Cairn has no pending-write or approval state in core (the separate "Agent activity digest and approvals" roadmap item names exactly this gap and is not built). Building that state to gate one feature would make this two roadmap items at once. Chosen instead: no new core capability. An agent that re-checks a page writes normally, `verified: true` per ADR-028, and the owner reviews it the way they review any agent write today, `/changes?who=agent` in the console. What's missing is only the discovery step: how an agent finds out what to check.

## Decision

1. A new shared operation, `listStalePages` (`packages/api/src/operations.ts`), returns pages in the Freshness screen's own order, pages never verified first (oldest updated first), then pages verified longest ago, each with id, title, parent id, `verified_at` (null for never), `updated_at`. Built the same way the console's existing `allPages` helper is, a bounded cursor walk over `DocumentStore.listPages` (already paginated), sorted in memory; no new store method, no new column, no new index.
2. **MCP**: a new tool, `list_stale_pages(limit?, cursor?)`, truncates to a token budget and returns a cursor when it does (hard rule 6). The server instructions gain one sentence: an agent asked to review what needs a re-check, or doing so on its own initiative, calls this tool, re-checks a page, and writes with `verified: true` when it still holds, per ADR-028. The skill gets the matching line. `pnpm context-cost` is run after, per this project's own rule 8.
3. **REST**: `GET /pages/stale`, same shape as `GET /pages/deleted` (ADR-059): paginated, JSON, no auth beyond what any other page-reading route needs.
4. **CLI**: `cairn stale [--limit N]`, printing a table the same way `cairn deleted` does today.
5. **Console**: `/freshness` is rewritten to call `listStalePages` instead of its own `allPages` plus filter-and-sort, so the four surfaces show the same order from the same code, per hard rule 14. The screen's existing two-group rendering (never verified, then verified) and its summary line are kept; `listStalePages`'s result carries enough (the never-verified count, the oldest verified page's time) to keep computing them without a second query.

## Consequences

1. An agent can now act on "what needs re-checking" without walking the whole page tree itself, the same gap ADR-011 asks every capability to close: the server tells the client what to do, not just what exists.
2. No approval workflow is built. A re-check is an ordinary write, visible to the owner after the fact through the existing changes feed, exactly as risky as any other agent write already is, no more and no less. If the owner later wants a hold-before-it-lands review, that is the separate, larger "Agent activity digest and approvals" item, not reopened here.
3. `list_stale_pages` needs a contract test with a realistic payload (verification checklist item 3), and the conformance suite is unaffected since no port method changed.
4. Rows have no `verified_at` (ADR-028 consequence 6 already declined this); `list_stale_pages` is pages only, same as the console screen it replaces the internals of.
