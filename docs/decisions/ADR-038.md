# ADR-038: A link to another Cairn's page is an edge, by its address alone

Status: accepted
Date: 2026-09-15
Relates to: ADR-002 (edges as documents), ADR-032 (the published wiki and its canonical address), ADR-037 (the local trusted list), PRD principle 6 (bridges between Cairns)

## Context

The roadmap's "Links to the original, across Cairns" already has two of its three parts. Every published page has one stable, canonical address (ADR-032: `<origin>/w/<page-id>`). Sources travel with a page unchanged through every path that touches it, publishing included (ADR-027), so a source pointing at another Cairn's page is never dropped. What is missing is the third part: "a link to a page in another Cairn is an edge like a local link."

Today a link inside a page's body becomes an edge in the graph (`packages/core/src/indexer/extract.ts`) only when it is `[[id]]` or `[label](cairn:id)` or `[label](/pages/id)`, an id in this workspace. An ordinary Markdown link to `https://a-friend's-cairn.example/w/pg_x` renders as a normal external link, safely, but the indexer never sees it: it does not appear in `cairn links`, `get_backlinks`, `get_neighbours`, or a page's neighbours in the console. A page that quotes or builds on another Cairn's page looks, to the graph, exactly like one that links to any other website.

Core's indexer is pure, by design: edges come only from what is written in a page's body, computed with no I/O, and rebuildable from scratch at any time (hard rule 9, PRD principle 4, "explicit over inferred"). Recognising a cross-Cairn link cannot depend on asking that address anything, or on checking it against the trusted list from ADR-037: that list decides who to accept a notice from later, not what counts as a link now. It has to be recognisable from the text alone.

ADR-032 already gives every Cairn's published page one address shape: `<origin>/w/<page-id>`. That shape is enough on its own to tell a reader, and the indexer, "this points at a page in a Cairn", the same way `cairn:id` tells it "this points at a page in this one".

## Decision

1. **A Markdown link whose address matches `<origin>/w/<id>`, any origin, is a cross-Cairn link**, recognised by `extractReferences` alongside the existing `[[id]]` and `cairn:id` forms. No new syntax: `[label](https://a-friend's-cairn.example/w/pg_x)` is an ordinary Markdown link already, and it keeps rendering as one, safely, exactly as before (`packages/api/src/web/markdown.ts` is unchanged: `https:` links already pass `SAFE_LINK`). Only the graph gains something.

2. **A new edge type, `cairn_link`.** `EdgeType` gains this value alongside `link`, `mention`, `relation`, `parent` and `tag`. Its `targetId` is the full external address, not a local id, the same way a `tag` edge's target is `tag:<name>`, not a page id: the edge model already carries a target that is not always a record in this workspace.

3. **`linkJson` (`packages/api/src/operations.ts`), read by MCP, REST and the CLI alike, reports a `cairn_link` edge as `{ cairn_url, type, label }` rather than guessing at a `page_id`.** Everywhere a page's links are shown, an outbound cross-Cairn link now appears beside its local ones, distinguished by carrying `cairn_url` instead of `page_id`.

4. **Nothing is checked, and nothing is fetched.** Recognition is structural: the address matches the shape, or it does not. Whether the page at the other end exists, still exists, or is really what it claims to be is exactly what `cairn check-sources` (ADR-036) and `cairn trust` (ADR-037) are for, run separately, by the owner's choice. This keeps extraction pure and edges rebuildable offline, unchanged from every edge type before it (rule 9).

5. **Inbound is still not tracked.** This Cairn cannot know that another one links to it without that Cairn saying so. That is "'Cited by', across Cairns", still `later`, and unaffected by this ADR beyond now having a real address shape to name in its notice.

## Consequences

1. One new edge type, one new regex, one branch in `linkJson`. No new port, no new storage column: `target_id` is already free text (`packages/adapter-sqlite/src/document-store.ts`'s `edges` table has no type constraint on it), and `EdgeType` is a plain string union with no database enum to migrate.
2. `cairn links <page-id>`, `get_backlinks`, `get_neighbours` and their REST equivalents now show a cross-Cairn link the same way they show a local one, each surface reading the same `linkJson`, so hard rule 14 holds without writing anything three times.
3. A link to another Cairn written before this ADR is picked up the next time that page is rebuilt or re-saved, the same as any indexer change; nothing is silently backfilled, and `cairn overview`'s counts are unaffected until then.
4. A link to a Cairn using a different path than `/w/<id>`, such as one behind a reverse proxy that rewrites it, is not recognised. That is an acceptable gap: the canonical address ADR-032 already promises is exactly `/w/<id>`, and a proxy that changes it has broken that promise on its own terms.
5. This still says nothing about whether the other Cairn is trustworthy, only that the owner or an agent wrote a link shaped like one of its pages. Trust is ADR-037's job, not this one's.
