# ADR-072: The vector margin miss on q17 is an accepted limitation, not a bug

Status: accepted

Date: 2026-09-23

Relates to: ADR-022 (vector search and the margin), ADR-042 (negation, found while investigating the same query)

## Context

`docs/ROADMAP.md` named a gap: for eval query q17 ("which peptide makes you really hungry"), the correct chunk (pg_ghrp-6, cosine 0.7246) is the single closest chunk in the workspace, but ADR-022's margin filter needs the top match to clear the mean similarity of the 10th-to-50th nearest chunks by `DEFAULT_MARGIN` (0.065), and this one falls short. The roadmap already flagged the obvious fix, shrinking the margin, as overfitting to one query, and asked for a real before/after evaluation before any change.

That evaluation was run before any code changed. Baseline, `pnpm eval`: keyword recall@5 0.88, hybrid recall@5 0.97 (31 of 32 scored queries). q17 is the only scored miss in either mode; keyword misses it too, so hybrid is not making things worse, it is failing to make this one case better. Hybrid mode already spends some precision to buy that recall: on the 9 queries with no answer in the workspace, keyword correctly returns nothing for 7, hybrid for only 4. The margin is the one knob controlling both numbers.

To find a fix that would not just trade one problem for the other, the actual similarity distribution behind q17 was inspected directly (temporary logging in `vectorRanking`, reverted after, `git status` confirmed clean): the top 250 nearest chunks to the query's embedding decay smoothly and monotonically from 0.7246 down to 0.59, with no elbow, no cliff, no separation between "real matches" and "background" anywhere in that range. This is because the workspace is one coherent topic (a peptide wiki) and "appetite" is a graded property across many of its pages, not a bimodal relevant/irrelevant split. The margin heuristic's premise, that the 10th-to-50th nearest chunks approximate a query-specific noise floor a real answer should stand out from, holds for most queries but does not hold here: ranks 10 to 50 are themselves legitimately appetite-adjacent content, so the baseline they produce is already close to the top match's own score.

Several alternatives to a flat margin cut were considered against that curve: a median instead of a mean baseline, a trimmed mean, a wider or shifted rank window, elbow detection. All of them assume a shape the curve does not have. Because the shape of "a real answer sitting at the front of a dense, on-topic cluster" and the shape of "a false match sitting at the front of a gradually decaying off-topic tail" are the same under every statistic tried, none of them can be told apart without risking the same false-positive cost the margin exists to prevent, and any of them would need to be validated against the same 41-query set that produced the current margin in the first place, exactly the overfitting the roadmap already warned against.

## Decision

Leave `DEFAULT_MARGIN`, `NEIGHBOURHOOD`, and `vectorRanking`'s baseline calculation as built. No code change. The roadmap's "vector margin misses a chunk in a dense topic cluster" item is closed as an investigated, accepted limitation: recall@5 stays at 0.97, and q17 is understood as a genuine boundary case, not a bug or a solvable gap left on the table.

A safe fix, if one is wanted later, is not a search-engine change: pg_ghrp-6's own page text could name "hunger" or "appetite-causing" more plainly, which would let keyword search answer this query directly (it does not today either) without touching the margin or risking any other query. That is a content edit, left to whoever maintains the peptide wiki, not assumed or made here.

## Consequences

1. `docs/ROADMAP.md`'s row for this item is marked done, pointing at this ADR, with the accepted-limitation framing instead of an open gap.
2. If the eval set grows, or a structurally different second pass (for example a small cross-encoder re-ranker) is ever proposed, this ADR's evidence, the shape of q17's own similarity curve, is the reason a margin-only fix was ruled out; a genuinely different mechanism would need its own ADR and its own before/after evaluation, not a revival of this one.
3. Hybrid search's existing trade, better recall on real questions, worse precision on no-answer ones, both riding on the same margin, is unchanged and is not itself reopened by this decision.
